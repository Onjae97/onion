# ASPICE 업무 규칙 (aspice-law)

이 저장소에서 ASPICE와 관련된 작업(규칙 해석, 산출물 점검, 자동화 도구 제작·수정)을 할 때 따르는 규칙이다.
**[확정]** = 사용자가 확정한 규칙, **[초안]** = 확인이 필요한 규칙. 초안은 확정 전까지 판단 근거로 쓰되, 결과에 "초안 규칙 적용"이라고 표시한다.

---

## 1. 기준 버전
- [초안] 적용 기준은 **Automotive SPICE PAM 3.1**이다.
- [초안] 프로젝트(고객사)가 4.0을 적용한다고 확인되면 이 항목을 바꾸고, 아래 BP 번호를 전부 다시 확인한다. **3.1과 4.0은 BP 번호·이름이 다르다.**
- 근거를 적을 때는 버전을 함께 쓴다. 예: `ASPICE 3.1 SUP.8.BP8`

## 2. 근거 표기
- 판단·지적·자동화 규칙에는 **근거 프로세스 ID + BP 또는 PA**를 단다. 예: `SUP.8.BP2 형상 항목 식별`, `PA 2.2 산출물 관리`.
- 근거를 모르면 지어내지 않는다. "근거 확인 필요"로 남기고 사람에게 묻는다.
- 표준 문구는 길게 옮겨 쓰지 않고 요약한다. 원문 확인이 필요하면 표준 문서의 위치(프로세스 ID·BP)를 안내한다.
- 표준 요구사항, 고객사 요구, 사내 규칙은 **구분해서 적는다.** (예: "ASPICE 요구 아님 — 고객사 CM 계획서 요구")

## 3. 판정 원칙
- [초안] AI는 **능력 수준(Level)이나 N/P/L/F 등급을 최종 판정하지 않는다.** 증거와 Gap(빠진 것·불일치)을 정리해 보여 주고, 판정은 평가자·담당자가 한다.
- **증거 기반.** "있을 것이다"로 판단하지 않는다. 산출물·기록·링크로 확인된 것만 충족으로 본다.
- **확인 실패 = 확인불가.** 조회 실패·권한 없음·파일 열기 실패는 충족/미충족으로 넘기지 않고 "확인불가"로 따로 남긴다. (CA-automation 공통 원칙과 동일)
- 산출물이 **있다**는 것과 **내용이 맞다**는 것은 따로 본다. 존재 확인만 했으면 "존재 확인(내용 미검토)"이라고 쓴다.

## 4. 작업 원칙
- **읽기 전용.** Codebeamer·Confluence 등 공식 저장소에는 쓰지 않는다. 결과는 항상 새 파일로 만든다.
- **공식 산출물 반영·저장·서명은 사람이 한다.**
- 회사 주소·프로젝트명·페이지 번호 등 실제 값은 저장소에 올리지 않는다. (`config.json`은 Git 제외, 예시는 가짜 값)
- 로그인 정보는 파일·로그·채팅에 남기지 않는다.
- 규칙을 바꾸면 이 파일의 해당 항목과 **변경 이력**(맨 아래)을 같이 고친다. 규칙 변경으로 기존 결과가 바뀌면 전후 차이를 보고한다.

## 5. 자주 쓰는 프로세스 (참고)
업무와 직접 닿는 프로세스만 적는다. 필요하면 추가한다.

| 프로세스 | 이름 | 이 업무와의 관계 |
| --- | --- | --- |
| SUP.8 | Configuration Management (형상 관리) | CM 담당 업무 전체, CA 대비 |
| SUP.10 | Change Request Management (변경 요청 관리) | 변경 이력·CR 추적 |
| SUP.9 | Problem Resolution Management (문제 해결 관리) | NC·문제 항목 조치 추적 |
| SUP.1 | Quality Assurance (품질 보증) | 감사·NC 관리 관점 |
| SYS.2~SYS.5 / SWE.1~SWE.6 | 시스템·SW 엔지니어링 | 양방향 추적성·일관성 BP → 추적성 자동화(AUTO-001) 근거 |

### SUP.8 BP (3.1 기준)
| BP | 내용 |
| --- | --- |
| BP1 | 형상 관리 전략 수립 |
| BP2 | 형상 항목(CI) 식별 |
| BP3 | 형상 관리 시스템 구축 |
| BP4 | 브랜치 관리 체계 수립 |
| BP5 | 변경·릴리스 통제 |
| BP6 | 베이스라인 수립 |
| BP7 | 형상 상태 보고 |
| BP8 | 형상 항목 정보 검증 (형상 감사) |
| BP9 | 형상 항목·베이스라인 보관 관리 |

- 형상 감사(CA)는 주로 **BP8**, CI list 관리는 **BP2**, 베이스라인은 **BP6**과 연결된다.

### 능력 수준 등급 (참고)
- N(Not) 0~15% / P(Partially) 15~50% / L(Largely) 50~85% / F(Fully) 85~100%
- Level 1 = PA 1.1(수행) / Level 2 = PA 2.1(수행 관리) + PA 2.2(산출물 관리) / Level 3 = PA 3.1(정의) + PA 3.2(배포)
